# Role & Objective
You are a Staff Full-Stack & ML Systems Engineer. Build a production-ready **Bank Statement Analyzer & SARIMA Spending Forecaster**, taking architectural and UI/UX inspiration from `https://github.com/sarthakroutray/FinWise`. 

The application accepts PDF bank statements, extracts tabular transaction records deterministically using `opendataloader-pdf`, stores normalized financial records in **Neon Serverless Postgres**, runs a **SARIMA (Seasonal AutoRegressive Integrated Moving Average)** time-series pipeline to forecast future spending with confidence intervals, and visualizes everything in a modern **Next.js** dashboard deployed on **Vercel**, backed by a serverless **FastAPI** application running on **Modal**.

---

## 1. Target Tech Stack & Deployment Topology
- **Frontend (Vercel):** Next.js (App Router, TypeScript), Tailwind CSS, shadcn/ui, Recharts (for historical vs. forecasted time-series ribbons), Lucide Icons, React Dropzone.
- **Backend & Compute (Modal):** FastAPI wrapped in a Modal ASGI deployment (`@modal.asgi_app()`), with heavy PDF extraction and SARIMA training offloaded to Modal background functions (`@app.function()`).
- **PDF Table Extraction:** `opendataloader-pdf` (Python wrapper over JVM CLI) outputting structured JSON/Markdown tables.
- **Time-Series Forecasting:** `statsmodels` (`SARIMAX`), `pandas`, `numpy`, `scikit-learn` (for RMSE/MAPE backtest metrics).
- **Database (Neon):** Serverless PostgreSQL (`asyncpg` + `SQLAlchemy 2.0` async ORM + `Pydantic v2`).

## 3. Critical Architectural & Implementation Specifications

### A. Modal Container Image & JVM Dependency (`backend/modal_app.py`)
1. **Java Runtime Requirement:** `opendataloader-pdf` spawns a local JVM process under the hood. You **MUST** configure the Modal image with OpenJDK 17 installed via `apt_install`:
   ```python
   import modal

   image = (
       modal.Image.debian_slim(python_version="3.11")
       .apt_install("openjdk-17-jre-headless", "procps")
       .pip_install(
           "fastapi[standard]",
           "sqlalchemy[asyncio]",
           "asyncpg",
           "pydantic-settings",
           "opendataloader-pdf>=2.5.0",
           "pandas",
           "numpy",
           "statsmodels",
           "scikit-learn",
           "python-multipart"
       )
   )
   ```
2. **Batch JVM Execution:** Because `opendataloader_pdf.convert()` initializes a JVM per call, write the uploaded PDF to a `tempfile.TemporaryDirectory()` and call `opendataloader_pdf.convert(input_path=[pdf_path], output_dir=tmp_out, format="json")` in a single invocation.
3. **Warm Containers:** Configure `min_containers=1` (or `keep_warm=1`) on the Modal ASGI function decorator during active testing to avoid cold-boot JVM overhead.

### B. PDF Table Extraction & Normalization (`backend/app/services/pdf_extractor.py` & `normalizer.py`)
1. Parse the JSON generated by `opendataloader-pdf`. Filter elements where `"type" == "table"`.
2. **Column Mapping Heuristics:** Bank statements vary in column headers (e.g., `Txn Date` / `Value Date` / `Date`, `Description` / `Particulars` / `Narration`, `Debit` / `Withdrawal` vs. `Credit` / `Deposit` vs. a single `Amount` column with `Dr/Cr` suffix, and `Balance`). Implement a resilient header-matching normalizer that maps raw table rows into a canonical schema:
   - `txn_date` (`DATE`)
   - `description` (`TEXT`)
   - `amount` (`NUMERIC(12, 2)`) — positive for spend/debit, negative or flagged via `txn_type` (`DEBIT` | `CREDIT`)
   - `balance` (`NUMERIC(12, 2)`, nullable)
   - `category` (`VARCHAR(64)`) — deterministic keyword/regex classifier (Food & Dining, Groceries, Utilities, Travel, Subscriptions, Transfers, Shopping, Other).
3. Deduplicate rows using a deterministic SHA-256 hash of `(txn_date, description, amount, balance)` stored in a `row_hash` column with a `UNIQUE` constraint so re-uploading overlapping statements is idempotent.

### C. Neon Serverless Postgres Schema (`backend/app/db.py` & `models.py`)
1. **Connection Pooling & String Format:** Ensure the database connection URL uses the `postgresql+asyncpg://` scheme with Neon's pooled hostname (`-pooler`). Since Modal spins up ephemeral containers and Neon uses PgBouncer, configure SQLAlchemy's `create_async_engine` with `poolclass=NullPool` and `connect_args={"ssl": "require"}`.
2. **Tables:**
   - `statements`: `id (UUID PK)`, `filename`, `uploaded_at`, `status (PROCESSING | COMPLETED | FAILED)`, `total_debit`, `total_credit`, `row_count`.
   - `transactions`: `id (UUID PK)`, `statement_id (FK)`, `txn_date (INDEX)`, `description`, `amount`, `txn_type (DEBIT | CREDIT)`, `category`, `balance`, `row_hash (UNIQUE)`.
   - `forecast_runs`: `id (UUID PK)`, `created_at`, `granularity (DAILY | WEEKLY)`, `horizon_steps (INT)`, `sarima_order (VARCHAR, e.g. "(1,1,1)x(1,1,1,7)")`, `aic (FLOAT)`, `rmse (FLOAT)`, `forecast_payload (JSONB)` (array of `{date, predicted, lower_ci, upper_ci}`).

### D. SARIMA Forecasting Engine (`backend/app/services/sarima_engine.py`)
1. **Time-Series Aggregation:**
   - Query all `DEBIT` transactions (excluding internal self-transfers if flagged).
   - Convert to a `pandas.Series` indexed by `txn_date`, resampled to either **Daily (`'D'`)** or **Weekly (`'W-MON'`)** frequency, filling missing intervals with `0.0`.
   - Apply IQR or 99th-percentile winsorization on extreme one-off outlier spikes (e.g., rent/tuition) or model them cleanly so they don't distort rolling variance.
2. **Stationarity & Order Selection:**
   - Run the Augmented Dickey-Fuller (`adfuller`) test to determine differencing order $d \in \{0, 1\}$ and seasonal differencing $D \in \{0, 1\}$ with seasonal period $s = 7$ (for daily data, capturing day-of-week spend cycles) or $s = 4$ (for weekly data, capturing monthly paycheck cycles).
   - Perform a fast, bounded AIC grid search over $p, q \in \{0, 1, 2\}$ and $P, Q \in \{0, 1\}$ using `statsmodels.tsa.statespace.sarimax.SARIMAX(..., enforce_stationarity=False, enforce_invertibility=False)`.
   - **Cold-Start Fallback:** If the uploaded statement spans fewer than $2 \times s$ data points, gracefully fall back to a non-seasonal `ARIMA(1, 1, 1)` or Holt-Winters Exponential Smoothing and flag this in the response metadata.
3. **Evaluation & Prediction:**
   - Hold out the last 15% of the series to compute out-of-sample `RMSE` and `MAE`.
   - Refit on 100% of the series and call `get_forecast(steps=horizon)`.
   - Extract `predicted_mean` and `conf_int(alpha=0.10)` (90% confidence intervals), clamping lower bounds at `0.0` (spending cannot be negative).

### E. API Endpoints (`backend/app/api/routes.py`)
- `POST /api/v1/statements/upload`: Accepts `UploadFile` (PDF), runs `opendataloader-pdf` extraction, normalizes and bulk-upserts transactions into Neon, and returns extraction summary + parsed rows.
- `GET /api/v1/transactions`: Paginated, filterable list of transactions (`start_date`, `end_date`, `category`, `txn_type`).
- `POST /api/v1/forecasts/generate`: Accepts `{ "granularity": "DAILY" | "WEEKLY", "horizon": 30 }`, triggers the SARIMA pipeline, stores the result in `forecast_runs`, and returns the historical series, forecasted series, confidence bounds, selected `(p,d,q)(P,D,Q,s)` order, AIC, and backtest RMSE.
- `GET /api/v1/analytics/summary`: Returns KPI metrics (Total Spend, Burn Rate, Top Categories, Month-over-Month delta, Next 30-Day Projected Spend).

Design a sleek, dark-mode-first financial analytics interface inspired by `FinWise`:

2. **Top KPI Ribbon:** 4 metric cards showing *Historical 30d Spend*, *SARIMA Projected Next 30d Spend* (with % delta badge), *Daily Average Burn*, and *Model Accuracy (RMSE / AIC badge)*.

4. **PDF Ingestion Drawer/Modal:** Drag-and-drop PDF uploader showing real-time extraction status (Upload -> JVM OpenDataLoader Table Extraction -> Transaction Normalization -> SARIMA Refit).
